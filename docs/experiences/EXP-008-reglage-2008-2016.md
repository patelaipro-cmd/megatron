# EXP-008 : réglage conjoint demi-vie / rétrécissement / w sur 2008-2016

Statut : **protocole figé le 29/10/2026, avant toute exécution**. Les résultats sont ajoutés dans une section séparée, sans modifier le protocole.

## Question

Demi-vie 90 et rétrécissement 3 ont été choisis sur une seule saison (Ligue 1 2022/23, EXP-001), puis w = 0,25 sur la même saison (EXP-004). Un réglage conjoint, choisi sur 8 saisons × 5 ligues, réduit-il l'écart de log-loss 1X2 avec le bookmaker (~0,02 à 0,025) ?

## Données

- `data/matches_top5_2000-2026.csv` + complément openfootball (`data.CURRENT`), PR #10. Seuls les matchs xgabora sont évalués (saisons ≤ 2025/26).
- Saison du 1er juillet au 30 juin. Historique de chaque ajustement : 3 ans au plus, matchs strictement antérieurs au jour prédit (`_check_past`).

## Découpage chronologique (5 ligues réunies, un seul réglage pour toutes)

- **Développement** : 2008/09 à 2015/16 (8 saisons). Sert à la grille.
- **Validation** : 2016/17 à 2019/20 (4 saisons).
- **Test** : 2020/21 à 2025/26 (6 saisons).

Le test n'est pas vierge : 2022/23 à 2025/26 ont servi à choisir ou tester `poisson-v1` et `poisson-v4` (EXP-001, EXP-004). Le nouveau réglage, lui, n'est choisi que sur 2008-2016. Validation 2016-2020 a servi à confirmer v4 (EXP-005) sans réglage.

## Grille (développement seulement)

Proxy cadres, a priori « moyenne », sans Dixon-Coles (EXP-002), max 1 095 jours :

- demi-vie ∈ {90, 135, 180, 270} jours (sous 90 rejeté par EXP-002) ;
- rétrécissement ∈ {2, 3, 5, 8} ;
- w ∈ {0,15 ; 0,25 ; 0,35}.

48 combinaisons, dont `poisson-v4` (90, 3, 0,25). Candidat = log-loss minimale sur le développement (5 ligues réunies). Si c'est `poisson-v4`, l'expérience conclut sans promotion.

Commande : `python scripts/grille_multi.py --saisons 2008/09,…,2015/16 --grille 90,135,180,270:2,3,5,8:0.15,0.25,0.35 --sortie docs/experiences/EXP-008/dev`, puis la même commande avec `--configs candidat=…,reference=90,3,0,moyenne,cadres,0.25` sur validation et test.

## Critères fixés avant exécution (candidat − `poisson-v4`)

- **V1** : validation, 5 ligues réunies, borne haute IC 95 % (bootstrap apparié, 2 000 tirages, graine 1) de l'écart de log-loss < 0.
- **T1** : test, 5 ligues réunies, borne haute IC 95 % < 0.
- **T2** : test, écart moyen < 0 dans au moins 4 ligues sur 5.
- **T3** : test, RPS du candidat ≤ RPS de `poisson-v4`.
- Information : écart avec le bookmaker, détail par saison.

## Décision prévue

- V1, T1, T2, T3 tenus : le candidat devient `poisson-v5` pour le 1X2 de l'agent Stats. Les marchés 2+ / 3+ gardent `poisson-v4-platt` (ajustement v4 séparé) jusqu'à une expérience dédiée, car la recalibration EXP-007 a été apprise sur v4.
- Sinon : `poisson-v4` reste en place.

## Retour arrière

Remettre demi-vie 90, rétrécissement 3, w 0,25 dans `StatsAgent`.

## Limites connues avant exécution

- Même source (Football-Data.co.uk via xgabora) que EXP-001 à EXP-007.
- Le test recoupe des saisons déjà vues (voir Découpage).
- Grille grossière ; un seul réglage pour 5 ligues.

- V1 tenu, T1 tenu, T2 tenu (5/5), T3 tenu.

## Limites

- Test recoupant des saisons déjà vues ; même source de données.
- Le bookmaker garde ~0,018 d'avance.
