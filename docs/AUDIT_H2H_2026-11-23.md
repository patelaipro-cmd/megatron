# Audit indépendant — H2H MEGATRON (23 novembre 2026)

## Périmètre
Comparaison GitHub `main...feature/h2h-retrieval-20261123`, workflows, adaptateur V1/V2, fixtures, historique complémentaire et sources déclarées. Audit **de code et de traçabilité**, pas une vérification exhaustive des scores sur les sites externes.

## Constats
- PR #79 fusionnée le 23/11/2026 ; l'adaptateur `megatron/h2h_readonly.py` et les branchements optionnels `syndicate.evaluer(h2h_csv=...)` et `goals.evaluate(h2h_csv=...)` figurent dans `main`.
- Trois commits de tests supplémentaires sur la branche, ouverts dans PR #80 (brouillon).
- GitHub Actions `tests` utilise `python -m unittest discover -s tests -t . -v` ; dernières exécutions de la branche réussies.
- Extraction H2H #45122331322 : 15 paires, 39/45 cellules H2H trouvées, 6 manquantes.
- Le fichier `data/fixtures_h2h_2026-11-23.csv` est une liste statique de **paires provisoires** : aucun contrôle de calendrier réel, heure de coup d'envoi ou état du match.
- `data/h2h_verifies_2026-11-23_SOURCES.md` référence des pages web, mais n'associe pas systématiquement une preuve indépendante horodatée à **chaque score**. Certaines références sont des pages de prévision du 23/11 plutôt que des fiches de match historique. La vérification externe des 39 scores reste **non démontrée**.
- Le CSV historique ne stocke ni URL de source par résultat, ni date de collecte, ni statut officiel/amical. Le cas Jong AZ–Jong Ajax inclut explicitement un amical sans champ de catégorie.
- `COMPLETE` dans l'adaptateur signifie uniquement trois lignes présentes, pas des données vérifiées.
- `h2h_readonly.lookup` coupe par **date civile** (`min(kickoff.date, at.date)`) ; les rencontres jouées le même jour avant l'analyse sont exclues même si leur heure est connue. Ce choix est conservateur mais réduit la couverture.
- `.github/workflows/h2h.yml` n'est déclenché sur push que pour l'ancienne branche `feature/h2h-retrieval-20261123` et utilise un calendrier fixé au 23/11. `workflow_dispatch` reste manuel ; pas de traitement quotidien réel dans `main`.
- Les H2H sont des **métadonnées opt-in** : ils ne modifient pas les probabilités V1/V2, leurs seuils ou la décision.

## Décision d'audit
**CONDITIONNEL — NE PAS ACTIVER EN PRODUCTION comme signal de validation.**
Le code est utilisable pour des tableaux expérimentaux en lecture seule. Les tests de non-régression sont verts ; cela ne valide pas la véracité des résultats ni le calendrier.

## Conditions avant approbation de PR #80 / activation
1. Prouver chaque H2H : date, score, domicile/extérieur, compétition, officiel/amical, URL de preuve et date de consultation.
2. Valider les fixtures avec identifiant de match, heure locale/fuseau, compétition et statut pas encore commencé.
3. Tester doublons, alias, équipes féminines/réserves, inversions de domicile et rejets de données futures.
4. Généraliser l'entrée du workflow aux fixtures datées du jour ; ne jamais présenter les 15 paires provisoires comme le programme réel.
5. Ajouter une porte qualité distincte : `COMPLETE` n'est jamais synonyme de `VERIFIED`.
6. Refaire une CI complète sur PR #80 et revoir le diff avant fusion. Aucun changement des coefficients.
